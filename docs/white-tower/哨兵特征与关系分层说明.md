# 哨兵特征池与关系分层 · 2026-10-15

这次完成了外貌抽取、亚种展开、人物资料保存和基础档案分层。无需调用 AI 即可生成一个有确定外貌的哨兵。代码位于本目录 `白塔卡源`，酒馆原入口和独立预览已使用这一版本。

## 已实装的特征池

| 类别 | 内容与数量 |
| --- | --- |
| 基础外貌 | 8种肤色、12种发色、10种发型、10种瞳色、10种体态 |
| 辨识特征 | 脸、身体、饰物、声音与小动作四池，每池16项，共64项；每人抽1～2项，来自不同池 |
| 气息 | 6种淡雅日常气息，多数新角色不附加气味；不再把机油、硝烟作为地域外貌 |
| 亚种 | 狐、狼、猫、猞猁、兔、鹿、羊、羽族、鳞族、水生，共10类；每类两组配套的身体特征 |
| 相处细节 | 8条通用生活习惯，以及每种亚人2条相关日常细节 |

例如，鹿型亚人会留意低矮门框，羽族会携带整理细羽的小梳子，水生亚人可能随身带保湿喷雾。耳尾、角、鳞和羽按同一种类配套抽取，保持原设定中的人类主体；精神体另外记录，不能拿精神体的物种替换本人的亚种。

地域影响肤色、发色的抽取倾向，同时保留跨地域的多样性。新角色的亚人概率：极北/极西40%，极南/极东25%，呼应原白塔“极北、极西亚种更常见”的设定。气息约30%概率出现；已有气味特征时不再叠加。上述概率集中在 `src/sxmnq/生成/形象.ts`。

异色瞳会选定两种不同颜色；眼镜、耳饰等也会落到确定结果。新人物描述中没有“银/白/灰”这样的待选项。临时绷带、刚出勤留下的气味不再作为新角色永久特征抽取；旧档原有特征记录仍保留。

## 人物怎样保持一致

人物生成时一次抽定 `形象`，之后候诊、接诊建档、复诊和治疗后剧情都读取这一份资料。实际治疗结算会把形象一起存入哨兵档案，MVU 更新回调保护已保存形象，避免模型回复更换外貌。

旧存档缺少具体外貌时，按姓名、地域、既有特征产生稳定的补全结果并写入变量。已有年龄、性格、关系数值和原特征不重新抽取。旧角色只有已记录“亚人/兽耳/兽尾”标记时才展开亚种，其余旧角色维持人类。旧聊天正文里曾由模型描写、却未写入变量的具体外貌不会自动被提取，需要有对应结构化资料才能准确继承。

资料结构同时由前端与变量脚本使用。原始 D 盘角色卡、世界书及真实聊天文件未覆盖；当前运行版本来自 C 盘构建。

## 现在的分层

| 阶段 | 界面展示 | 程序处理 |
| --- | --- | --- |
| 初见 | 年龄、地域、外貌、亚种、辨识特征、精神体 | 无需关系数值，读取已存形象 |
| 信赖达到20 | 相处细节 | 显示一条固定生活习惯，治疗后对话提示可自然提及 |
| 信赖达到40 | 深入档案 | 开放已有B面性格，治疗后对话提示允许逐步表现 |

查看档案不涨数值、不扣时段。信赖表示熟悉程度和对疏导的信任，不能替代恋爱确认或身体接触意愿；耳尾等身体特征也不会自动带来亲近许可。

这里的隐藏是界面展示与治疗后对话提示的分层，不是数据加密：资料保存在游戏变量中。普通聊天仍受酒馆实际启用的世界书和提示词影响。修改版世界书规则已补充相同约定，待正式导出卡片时合并；当前已生效的治疗请求会直接附带外貌及分层提示。

## 原 EJS 到底做了什么

已读取原 `[哨向]白塔.png` 的相关条目。原卡 `固定开启—EJS_哨兵私密` 读取的是 `出场角色.<姓名>.私密档案` 与 `信任度`，其第二层、第三层主要阈值为20、40，另有资料已填写或剧情已发生的分支。EJS负责判断“这次发送哪些资料与指令”；资料填写和正文描写仍由模型完成。

目前 `哨向模拟器` 使用 `哨兵.<姓名>.信赖/好感`，未包含原来的完整私密档案结构和 EJS 条目。不能把原 EJS 原封不动粘回来：变量路径不同、资料字段缺失、治疗信赖也不等于情感关系。本次恢复的是上述基础了解分层，并未移植旧完整成人私密档案。

后续关系系统建议明确区分三件事：

1. **数值条件**：决定是否有机会了解更多、是否出现邀约选项。
2. **相处与关系确认**：用实际事件记录约会、表白和双方回应，不能只靠送礼累计就自动成为恋人。
3. **资料展示**：程序决定当前可展示哪些已经保存的内容；模型只负责把已发生的互动写成剧情。

一个需要单独调整的旧问题：当前 `分档.ts` 的好感阈值仍为3/6/9/12，而好感字段范围是0～100；到12的原文就会要求频繁求婚。赠礼系统加入后，这个节奏尤其容易过快。本次保留其数值和旧分档，避免顺带改变正在游玩的关系；后续应先统一好感尺度与关系确认规则，再迁移更深层内容。
