# 新哨兵姓名与伤情（2026-10-19）

程序继续生成等级、污染度、年龄、地域、精神体、外貌、亚种、性格、诊金等底层资料。仅新哨兵的姓名和战损来源改由酒馆当前 API 批量填写，不调用额外图片服务。

## 游玩流程

1. 日期变化时，程序先确定当天名单与回头客。
2. 白塔值班日的新哨兵在首次接诊前静默请求一次 `generateRaw`。第一天先读完序章，再开始整理病例；休息日不自动请求。
3. 模型收到原白塔命名规则、每人明确的字数和中西分支、角色资料、近期姓名与伤情。返回每人编号、姓名和35～80字伤情；不携带聊天历史，不新增聊天楼层。
4. 整批校验人数、编号、姓名长度、禁用姓名、重名、伤情长度和重复等。全部通过才写入名单，数值与外貌不会被模型输出覆盖。语感和伤情合理性通过提示词约束，不能机械保证每次都理想。
5. 生成过程中不展示临时姓名。可以取消；接口失败、超时、缺人或重名显示重试按钮，失败时不部分写入。请求90秒超时；旧请求过期返回不会替换新名单。

## 存档兼容

- 旧存档的当前名单默认沿用，不自动给已经展示过的人改名；以后新生成的名单启用新流程。
- 复诊角色不重新命名，保留原有档案。伤情文案此次只接管新哨兵；老角色复诊逻辑继续沿用。
- 结果保存在 `今日.申请列表`；`今日.人物文案` 保存生成状态、编号和最近40份姓名/伤情记录。重试沿用同一批数值与外貌，不重新掷骰。
- 首次生成中断后，重新打开会提供重试，不悄悄恢复旧模板继续接诊。
- 白塔的变量更新保护现在同时保护整个 `今日`，防止后续剧情模型清空或改写程序确定的名单和生成记录。
- 独立预览没有真实酒馆 API 时会提示连接 API；界面测试使用模拟响应，没有调用玩家真实模型账户。

## 主要文件与测试

`生成/文案.ts`：准备、提示词、解析校验、原子应用、取消与超时。

`界面/共用/掷骰接线.ts`：新名单完成后设置生成状态。`界面/申请/App.vue`：生成提示、取消与重试。`schema.ts`：旧档默认值。变量结构脚本保护存档。

`check-npc-copy.mjs` 检查旧档、复诊身份、数值外貌保持、存档往返、不完整/重复/错误响应、取消、缺少API、过期返回、响应期间数据对象更新、MVU保护。

`check-npc-copy-ui.mjs` 用模拟API验证四种尺寸、生成前隐藏名单、单次请求、取消、缺人后重试、迟到响应不覆盖、逐人展示及不新增聊天楼层。
