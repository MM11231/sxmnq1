# 家园与家具 · ① 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「买家具」和「摆家具」合成一件事 —— 点九宫格里的格子，商店就在那里出现；床位与气氛由摆出来的家具派生，诊所从「一张床」长成「五间房」。

**Architecture:** 新增 `src/sxmnq/家园/` 一层纯函数（物品表 / 两层房型图 / 家具派生与动作 / 九宫格视图模型），全部不依赖酒馆、可在 node 里直接跑测试。`诊所.床位` 从存储字段**删除**，与新的 `诊所.家具` 数组一起把床位、气氛、摆位、仓库全部变成派生值。界面侧把原来那张「诊所与申请」折叠区拆成三个互斥块（诊所 ｜ 申请 ｜ 家园），家园块是一个两层的九宫格。

**Tech Stack:** TypeScript + Vue 3 + zod 4 + lodash + pinia；测试用 node 内置 `.mjs` + 手写断言（工程里没有 vitest/jest）。Node 可 `import` `.ts`（类型擦除），但**必须**先 `import '../../测试钩子.mjs'`。

**Spec:** `docs/superpowers/specs/2026-09-28-家园与家具-design.md`

## 本计划相对 spec §11 的排布调整

spec §11 给的是六步大纲，本计划把它铺成七个任务，有两处**顺序上的细化**，都不改变设计：

1. **「物品表」提前到 schema 之前。** spec 把物品表放在第 4 步，但第 2 步的存档迁移要**播种一张折叠床**（§8.1）、气氛要**由家具汇总**（§7.2）—— 两者都得先有表和家具模块。所以 Task 2 建常量表、Task 3 建家具模块、Task 5 才动 schema。
2. **`布局.ts`（九宫格视图模型）单独成一层。** spec 只说「一个九宫格组件喂不同的数据」。本计划把「喂什么数据」也抽成纯函数放在 `家园/布局.ts`，让 `九宫格.vue` 只干渲染 —— 否则那段逻辑住在 `.vue` 里，node 跑不了测试。

顺序上唯一**不能动**的是 Task 5 必须紧跟 Task 1~4：`诊所.床位` 是破坏性变更，schema 与调用点必须同时落地（spec §11）。

## 这个计划**不做**什么

写下来是因为每一条都容易在实现时被顺手做了，而它们都是**故意不做**的：

| 不做 | 出处 | 为什么 |
|---|---|---|
| **正文区不动**。九宫格只在手风琴的第三块里，不接管正文区 | spec §9.2 | 你早先说「点家园就把正文换成九宫格」是在选「手风琴互斥」**之前**。L2/L3 已经两层下钻，再叠一个「正文区被换掉」会让「我在哪一层」变难判断 |
| **L1（家的总览）不做** | spec §3.2 | 那是 ②。① 的家园块根就是 L2，门 = 收起 |
| **格子不能拖拽** | spec R3 | 家具靠「点格子 → 弹层里换」来移动，不做 drag & drop。前序 §6.3 已定 |
| **不做居住 / 分房** | spec §2.3 | 升格成 ③ 了 |
| **不删 `疗效`** | spec §10 尾 | 它**从来没有任何代码读过**。没有可删的东西，只要不写就行 —— 所以 Task 1 Step 13 那条 grep 期望的是**空** |
| **不动 `界面/状态栏/结算.ts` 的目录位置** | 本计划 | 它是结算的数学，跟「状态栏」这个界面名已经脱钩；但搬它会牵动 `结算.test.mjs` 与三处 import，不值当 |

/**
 * 家具物品表。**这是全工程唯一一处定义「一件家具值多少」的地方。**
 *
 * 前序 §6.1 原来有四个效果字段 (床位 / 疗效 / 减耗 / 氛围), 本子项目删到只剩氛围
 * —— 疗法侧那两条整个下线了 (spec §2.1)。
 *
 * 床**不写「床位 +1」这个字段**: 一件床给几个床位恒为 1, 所以床位是**数出来的**
 * (见 家具.ts 的 算床位), 不是每件物品各写一遍 —— 写一遍就多一处能写错。
 *
 * 数字全部来自 spec §6.1 / §6.2, **是待调的保守值** (前序 §15 待定 #1):
 * 定价原则是「一件功能家具 ≈ 3–5 场 D 级治疗的收入」。
 */

export type 家具类型 = '床' | '装饰';

export interface 物品 {
  名称: string;
  类型: 家具类型;
  /** 摆出来之后加多少气氛 (spec §7.2) */
  氛围: number;
  /** 买它要多少金 */
  价钱: number;
}

/** 商店的全部货。床从便宜到贵就是升级路线 (spec §6.1)。 */
export const 物品表: readonly 物品[] = [
  { 名称: '折叠床', 类型: '床', 氛围: 10, 价钱: 300 },
  { 名称: '单人床', 类型: '床', 氛围: 25, 价钱: 700 },
  { 名称: '诊疗床', 类型: '床', 氛围: 45, 价钱: 1400 },

  { 名称: '素色窗帘', 类型: '装饰', 氛围: 8, 价钱: 60 },
  { 名称: '旧书架', 类型: '装饰', 氛围: 12, 价钱: 100 },
  { 名称: '助眠香薰', 类型: '装饰', 氛围: 15, 价钱: 120 },
  { 名称: '诊疗躺椅', 类型: '装饰', 氛围: 18, 价钱: 150 },
  { 名称: '恒温灯', 类型: '装饰', 氛围: 22, 价钱: 180 },
];

/**
 * 找不到就返回 `undefined`, **不要抛** —— 存档里的家具名可能对不上表
 * (改过表、或者玩家自己写进去过)。为一个名字让整个界面崩掉不划算,
 * 界面上表现为「这件家具没有名字」总比白屏强。
 */
export function 找物品(名称: string): 物品 | undefined {
  return 物品表.find(物 => 物.名称 === 名称);
}

/** 某个类型能买的全货, 由便宜到贵。空格子的弹层列这个 (spec §5)。 */
export function 同类物品(类型: 家具类型): 物品[] {
  return 物品表.filter(物 => 物.类型 === 类型);
}

/**
 * 同类型里比它贵的那些, 由便宜到贵。格子上已经有东西时, 弹层列的是这个
 * —— 「换成更好的」而不是「还能买什么」(spec §5)。
 *
 * 已经是顶配就返回空数组, 界面据此只显示「收起来」。
 */
export function 更贵的同类(名称: string): 物品[] {
  const 现在 = 找物品(名称);
  if (!现在) return [];
  return 物品表.filter(物 => 物.类型 === 现在.类型 && 物.价钱 > 现在.价钱);
}

```ts
/**
 * 家具的派生值与动作。
 *
 * **`诊所.家具` 数组是唯一的真值源** (spec §8): 一件家具「摆在哪」写在它自己的
 * `在哪` 上, 不另存一张摆位表 —— 那样会出现「摆位指向一件已经不存在的家具」
 * 这种修不好的坏状态。同款买两件也不需要额外机制, 数组天然允许。
 *
 * 本模块里所有 `算*` 都是纯函数, **不进 schema**; 只有 `气氛` 是持久化的派生值
 * (写在 schema 里、每次解析时重算, 照 `$称号` 的既有做法)。
 *
 * 动作 (收起来 / 摆上 / 从仓库摆) 是**就地改数组**的 —— 传进来的是 store 里那个
 * 响应式数组, 改完由 store 的深度监听写回变量。这和 结算.ts 的 应用结算 一个路子。
 */
import { 开局床位 } from './房型';
import { 找物品, type 家具类型, type 物品 } from './物品';

export interface 家具件 {
  名称: string;
  类型: 家具类型;
  /** 摆出来才加气氛。它跟着家具走而不是每次去查表, 是为了改表之后老存档不变样 */
  氛围: number;
  /** `''` = 还在仓库。否则是 `${房间}·${方位}`, 如 `一号·北` (spec §8) */
  在哪: string;
}

/**
 * 数组下标 + 那件家具。**两个一起带着走** ——
 * 同款买了两件时, 光凭名称分不出要动的是哪一件。
 */
export interface 带序 {
  序: number;
  件: 家具件;
}

/** `一号·北` → `一号`。空字符串(仓库)原样返回空字符串 */
export function 房间名(在哪: string): string {
  return 在哪.split('·')[0] ?? '';
}

/** 仓库 = 买了还没摆的 (spec §6.3)。它就是「家园」按钮上那个角标。 */
export function 算仓库(家具: 家具件[]): 带序[] {
  return 家具.map((件, 序) => ({ 序, 件 })).filter(项 => !项.件.在哪);
}

/** 摆位: `一号·北` → 那件家具。空格子不在里面 —— 界面判「有没有」就是查它。 */
export function 算摆位(家具: 家具件[]): Record<string, 带序> {
  const 表: Record<string, 带序> = {};
  家具.forEach((件, 序) => {
    if (件.在哪) 表[件.在哪] = { 序, 件 };
  });
  return 表;
}

/**
 * 床位 = 摆出来的床有几张 (spec §7.1)。**这是「床位」唯一的定义** ——
 * 它不再是变量。前序 §5.2 那道床位闸门 (能接诊吗) 逻辑一个字没改,
 * 只是入参从写死的数字换成了这个。
 */
export function 算床位(家具: 家具件[]): number {
  return 家具.filter(件 => 件.在哪 && 件.类型 === '床').length;
}

/**
 * 气氛 = 摆出来的家具的氛围之和 (spec §7.2)。**本身不封顶** ——
 * 封顶的是它换来的信赖加成。仓库里的不算。
 */
export function 算气氛(家具: 家具件[]): number {
  return 家具.reduce((和, 件) => (件.在哪 ? 和 + 件.氛围 : 和), 0);
}

/** 气氛换来的信赖加成。硬上限 +5 —— 前序 §7 就是这么定的 (spec §7.2) */
export function 算信赖加成(气氛: number): number {
  return Math.min(5, Math.floor(气氛 / 20));
}

/** 气氛的档位描述 (spec §9.3)。状态栏里那一句就是它。 */
export function 气氛档(气氛: number): string {
  if (气氛 >= 60) return '让人不想走';
  if (气氛 >= 40) return '待着舒服';
  if (气氛 >= 20) return '还算整洁';
  return '有点冷清';
}

/**
 * 一个房间里摆了几件、几张床、多少氛围 —— L2 那张房间卡上的小字。
 *
 * 按**解析出来的房间名**比, 不用 `startsWith`: 房间名是 `一号` 的时候,
 * `startsWith` 会把 `十一号·北` 也算进来。
 */
export function 房间概况(家具: 家具件[], 房名: string): { 床: number; 件: number; 氛围: number } {
  const 在里面 = 家具.filter(件 => 件.在哪 && 房间名(件.在哪) === 房名);
  return {
    床: 在里面.filter(件 => 件.类型 === '床').length,
    件: 在里面.length,
    氛围: 在里面.reduce((和, 件) => 和 + 件.氛围, 0),
  };
}

/**
 * 开局那张折叠床 (spec §8.1)。
 *
 * 老存档里 `诊所.床位 = 1`、没有 `家具`, 新 schema 派生出来的床位会是 **0**
 * —— 等于把所有人的开局那张床弄丢了。空数组 == 开局态 (本卡没有「卖掉所有家具」
 * 这条路), 所以拿它当判据播种是幂等的。
 *
 * 数值照物品表取, **不另写一个数**: 表改了这里跟着改, 不会悄悄脱钩。
 */
export function 开局家具(): 家具件[] {
  const 床 = 找物品('折叠床');
  if (!床) throw Error('物品表里没有「折叠床」—— 开局那张床是照它播种的 (spec §8.1)');
  return [{ 名称: 床.名称, 类型: 床.类型, 氛围: 床.氛围, 在哪: 开局床位 }];
}

/**
 * 把一个格子清空: 那件家具**退回仓库**, 不是卖掉 (spec §5)。
 * 于是「给一号房换诊疗床」顺带就把退下来的折叠床给了二号房。
 */
export function 收起来(家具: 家具件[], 在哪: string): void {
  const 项 = 算摆位(家具)[在哪];
  if (项) 项.件.在哪 = '';
}

/**
 * 买一件并**直接摆进这个格子** (spec §5: 从这里买就直接摆上, 不要求先去仓库取)。
 * 格子上原来那件退回仓库 —— 这就是「换成更好的床」。
 *
 * 扣钱**不在这里**: 钱在 `主角.金钱` 上, 是另一个字段, 由调用方先确认买得起。
 * 本函数只管 `家具` 数组这一件事。
 */
export function 摆上(家具: 家具件[], 在哪: string, 物: 物品): void {
  收起来(家具, 在哪);
  家具.push({ 名称: 物.名称, 类型: 物.类型, 氛围: 物.氛围, 在哪 });
}

/** 把仓库里第 `序` 件摆进这个格子 (spec §5 的「这里能放的」) */
export function 从仓库摆(家具: 家具件[], 序: number, 在哪: string): void {
  const 件 = 家具[序];
  if (!件) return;
  收起来(家具, 在哪);
  件.在哪 = 在哪;
}
```

```ts
/**
 * 九宫格的**视图模型** —— 把「房型 + 家具」烤成九张格子卡该显示什么。
 *
 * 单开这一层是为了让 `九宫格.vue` 只干渲染: 组件不该知道 `一号·北` 这种键是怎么
 * 拼的, 也不该知道 L2 的房间卡副标题写「床位 1」还是「空着」。那些住在 `.vue` 里
 * 就没法在 node 里测 —— 而 `.vue` 文件 node 直接 import 不了。
 *
 * 三层共用同一个组件、同一套格子, 只是喂进来的数据不同 (spec §4):
 * L1 全是房间卡 (② 才做), L2 是房间卡 + 门 + 过道, L3 是床 / 自由 / 门 / 灰。
 */
import { 算摆位, 房间概况, type 家具件 } from './家具';
import { 三层房型, 二层房型, type 方位, type 格类 } from './房型';

/** 一张格子卡。`主` 是那行大字, `副` 是底下的小字 */
export interface 宫格 {
  方位: 方位;
  类: 格类;
  主: string;
  /** 小字第二行。没有就单行 */
  副?: string;
  可点: boolean;
}

/** L2 · 诊所: 五张房间卡 + 一扇门 + 三条过道 */
export function 二层格子(家具: 家具件[]): 宫格[] {
  return 二层房型.map(格 => {
    if (格.类 === '房间') {
      const 概况 = 房间概况(家具, 格.房名 ?? '');
      return {
        方位: 格.方位,
        类: 格.类,
        主: 格.房名 ?? '',
        副: 概况.床 ? `▶ 床位 ${概况.床}` : '▶ 空着',
        可点: true,
      };
    }
    if (格.类 === '门') return { 方位: 格.方位, 类: 格.类, 主: '门', 副: '返回', 可点: true };
    // 过道: 不写字、点不动。三格连成一条带子才看得出那是走廊 (spec §4.1)
    return { 方位: 格.方位, 类: 格.类, 主: '', 可点: false };
  });
}

/**
 * L3 · 一间房。
 *
 * 格子上摆了东西就显示**家具名**; 空着就显示它收什么 —— 「空床」与「自由」
 * 一眼分得出这个格子是干嘛的 (spec §4.1)。
 */
export function 三层格子(家具: 家具件[], 房名: string): 宫格[] {
  const 摆位 = 算摆位(家具);
  return 三层房型.map(格 => {
    const 摆着的 = 摆位[`${房名}·${格.方位}`]?.件.名称;
    if (格.类 === '床') return { 方位: 格.方位, 类: 格.类, 主: 摆着的 ?? '空床', 可点: true };
    if (格.类 === '自由') return { 方位: 格.方位, 类: 格.类, 主: 摆着的 ?? '自由', 可点: true };
    if (格.类 === '门') return { 方位: 格.方位, 类: 格.类, 主: '门', 副: '返回', 可点: true };
    return { 方位: 格.方位, 类: 格.类, 主: '', 可点: false };
  });
}
```

function 算预计线数(姓名: string, 等级: 等级, 污染度: number) {

    哨兵等级: 等级,
    主角等级: 数据.value.诊所.等级,
    信赖: 数据.value.哨兵[姓名]?.信赖 ?? 0,

    // 但少写一个必填字段 `ts-loader` 是 transpileOnly, **不会报错** ——

      污染度: 项.污染度,

      线数: 算预计线数(姓名, 项.等级, 项.污染度),

      // 回头客重新出现在申请列表时, 只有申请列表是他此刻最新的状态 (同 应用结算)。
      预计次数: 算预计次数(项.污染度, 算单次清除量(数据.value.诊所.等级)),

async function 结束(果: 治疗结果) {
  const 患 = 诊疗.value;
  if (!患) return;

  const 申 = 数据.value.今日.申请列表[患.姓名];
  const 旧 = 数据.value.哨兵[患.姓名];

  // 首次接诊时 应用结算 会照 患者 就地建档, 所以这里必须把**整份档案**带上。
  // 少一个字段, schema 的 prefault 就会把它悄悄填成空串 —— 界面上表现为
  // 「这个病人没有精神体」, 而哪里都不报错。
  //
  // 以申请列表那一份为准(它是这个人此刻最新的状态), 没有才退回已有的哨兵记录。
  const 档 = 申 ?? 旧;

  // 先把结算时的状态拍下来 —— 元指令描述的是这一场**开始时**的处境,
  // 而应用结算会就地改掉精神力、名声这些东西。
  const 上: 结算上下文 = {
    世界: { 日期: 数据.value.世界.日期, 时段: 数据.value.世界.时段 },
    主角: {
      姓名: 数据.value.主角.姓名,
      精神力: 数据.value.主角.精神力,
      精神力上限: 数据.value.主角.精神力上限,
    },
    诊所: {
      名称: 数据.value.诊所.名称,
      等级: 数据.value.诊所.等级,
      $称号: 数据.value.诊所.$称号,
      名声: 数据.value.诊所.名声,
      床位: 床位.value,
    },
    // ★ 真的接上了 —— 装修好的诊所, 结算文案会不一样 (spec §7.3)
    气氛: 数据.value.诊所.气氛,
    患者: {
      姓名: 患.姓名,
      等级: 患.参数.哨兵等级,
      污染度: 患.参数.污染度,
      战损来源: 档?.战损来源 ?? '',
      年龄: 档?.年龄 ?? 25,
      地域: 档?.地域 ?? '',
      精神体: 档?.精神体 ?? { 纲: '', 方向: '', 栖息: '', 体型: '', 危险: '' },
      特征: 档?.特征 ?? [],
      A面: 档?.A面 ?? '',
      B面: 档?.B面 ?? '',
      信赖: 旧?.信赖 ?? 0,
      好感: 旧?.好感 ?? 0,
      基础诊金: 申?.诊金 ?? 0,
      $信赖: 旧?.$信赖 ?? '',
      $好感: 旧?.$好感 ?? '',
    },
  };

  const 收益 = 应用结算(store.data, 上, 果);
  诊疗.value = null;

  await createChatMessages([{ role: 'user', message: 构建元指令(上, 果) }]);
  await triggerSlash('/trigger');

  toastr.success(`评级 ${果.评级}　诊金 +${收益.诊金}　名声 +${收益.名声}`, '疏导结束');
}
</script>
