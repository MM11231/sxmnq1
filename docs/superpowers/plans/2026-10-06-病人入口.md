# 病人入口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让正文里推门进来的哨兵自动出现在前端「申请治疗」列表里 —— 把 AI 的动作从「回填 `待登记[i].姓名`」（簿记，它不做）换成「往 `今日.登场` 追加一条」（叙事，它本来就在做）。

**Architecture:** 新增一个只写不读中间态的变量 `今日.登场`。AI 每次让一个人登场就往里 append 一条 `{姓名, 战损来源, 自创}`；前端一个纯函数 `处理登场` 按 FIFO 从 `待登记` 取最上面那张掷好的单子配给他，写进 `申请列表`，然后清空 `登场`。这条新路与老的「AI 回填姓名」并存 —— 老路降级成兼容回路，接住还没更新世界书的安装。全部逻辑在 `生成/流转.ts` 里，是纯函数，能在 node 里直跑测试。

**Tech Stack:** TypeScript + Vue 3 + Pinia + zod 4 + SCSS，webpack 打包；MVU 变量框架（`stat_data` + JSON Patch）；测试是 `node <文件>.test.mjs` 直跑的裸脚本，无框架。

**Spec:** `docs/superpowers/specs/2026-10-06-病人入口-design.md`

## Global Constraints

- **每个新字段都必须有 `.prefault(...)`。** MVU 会 parse **整份** `stat_data`，少一个字段就 `safeParse` 失败，而失败是静默的 —— `util/mvu.ts` 里 `if (result.error) return`，界面上只表现为「所有数字变回默认值」。
- **`登场` 的条目形状逐字如此**：`{ 姓名: string, 战损来源: string, 自创: boolean }`。`自创` 缺省 `false`。
- **逐字段搬运，不用展开语法。** 这是为了让 `待登记条目` 以后加字段时**编译不过**，而不是静默漏掉（`流转.ts:77` 那条注释）。
- **不做老存档迁移。** `登场` 靠 `prefault([])` 兜底，零迁移代码。
- **界面文案逐字**：`今天还有 {N} 个人没露面`、`未到 · {NN}`。
- **组件 import 名必须 ASCII**（`import TreatmentPanel`）。中文标签名会被当纯文本渲染、绑定全丢，只有生产构建才发作且构建照报成功。
- **标识符与注释用中文**，与既有代码一致。
- **测试脚本**：`node src/sxmnq/生成/流转.test.mjs` / `node src/sxmnq/schema.test.mjs`。断言用文件里现成的 `断言(条件, 说明)` 和 `等于(实得, 期望, 说明)`，收尾 `process.exit(fail === 0 ? 0 : 1)`。
- **不要碰 `哨兵`。** 本子项目只写 `今日`。`哨兵[x].状态='在诊'` 之后的可达性是子项目乙的事。

## Review Focus

这五类输入 spec 没写、也没有哪个任务的测试天然会覆盖，但最可能咬到玩家。每一条都在它所属的任务里配了测试。

1. **AI 写的姓名带前后空格**（`" 沈砚"`）—— 期望 trim 之后再当 key，否则 `申请列表` 里会同时存在 `"沈砚"` 和 `"沈砚 "` 两个病人。**最可能发生**：AI 拼 JSON 时手滑加空格是常态。
2. **`自创` 字段整个缺失**（不是 `false`，是没这个键）—— 期望当 `false` 处理，照常占用单子。搞反的话每次报到都会白烧一张卡。
3. **`登场` 比 `待登记` 长**（AI 一楼塞了 4 个人，桌上只剩 2 张单子）—— 期望前两个吃单子、后两个现掷，不抛异常、不重复用同一张。
4. **战损来源是纯空格**（`" "`）—— 它是 truthy，`||` 兜底会失效，病人的战损来源会变成一个空格。期望 trim 后再判空。
5. **AI 整局都不写 `登场`** —— 期望不崩、界面照常显示「今天还有 N 个人没露面」，而不是静默假装没这个功能。这一条**只能靠 Task 5 在真酒馆里跑一遍**才验得出来。

export function 晋级已命名的(今日: 今日数据): string[] {
  const 晋级: string[] = [];
  const 留下: 待登记条目[] = [];

  for (const 条 of 今日.待登记) {
    const 名 = (条.姓名 ?? '').trim();
    if (!名) {
      留下.push(条);
      continue;
    }
    // 同名已经在申请列表里 → **丢掉**这张单子, 而不是留回去。
    // 同名说明 AI 把一个人写了两遍, 没有第二个人在等它;
    // 留回去的话 待登记 永远不会归零, 界面上「还有 N 个人没露面」会一直挂着。
    //
    // ⚠ 这与 处理登场 的重名处理**故意相反** —— 那边撞名要**留着**单子,
    //   因为在那条路上单子是一张还没人用的卡。别把两处抄成一样。
    if (今日.申请列表[名]) {
      console.warn(`[流转] 待登记 里的「${名}」已在申请列表里, 丢掉这张单子`);
      continue;

    今日.申请列表[名] = 转申请(条, 条.战损来源);
    晋级.push(名);
  }

  今日.待登记 = 留下;

**4f. 新增 `处理登场`。** 紧跟在 `晋级已命名的` 之后：

```ts
/**
 * 把 AI 报到的人配进 申请列表。**就地改 今日**, 返回收了谁。
 *
 * 配对是 **FIFO**（spec §4.1）: 取 待登记 最上面那张, 用它的掷定值。
 * 单子用完了、或者这条标了 自创, 就现掷一个 —— 等级仍然走诊所等级的闸门,
 * 不会凭空冒出高级哨兵。
 *
 * **重名一律跳过, 而且不动 待登记** —— 那张单子是一张还没人用的卡,
 * 该留给下一个真进来的人。与 晋级已命名的 的处理**故意相反** (见那边的注释)。
 *
 * 幂等靠「处理完清空 登场」, 不靠日期戳。
 */
export function 处理登场(
  今日: 今日数据,
  诊所等级: 等级,
  随机: 随机源 = Math.random,
): string[] {
  const 收了: string[] = [];

  for (const 报 of 今日.登场) {
    const 名 = (报.姓名 ?? '').trim();
    if (!名) continue; // AI 写半截是常态, 不当成错误

    if (今日.申请列表[名]) {
      console.warn(`[流转] 登场 里的「${名}」已在申请列表里, 跳过 (不消耗申请单)`);
      continue;
    }

    // 自创 (或单子用完了) → 现掷
    const 单 = 报.自创 === true ? undefined : 今日.待登记.shift();
    const 底 = 单 ?? 掷一个(诊所等级, 随机);
    // AI 写的战损来源优先, 但**先 trim 再判空** —— 纯空格是 truthy,
    // 不 trim 的话 `||` 兜底会失效, 病人的战损来源会变成一个空格。
    const 战损 = (报.战损来源 ?? '').trim() || 底.战损来源;

    今日.申请列表[名] = 转申请(底, 战损);
    收了.push(名);
  }

  今日.登场 = [];
  return 收了;
}
```

export function 跑一次(
  今日: 今日数据,
  当前日期: string,
  诊所等级: 等级,
  随机: 随机源 = Math.random,
): 流转结果 {
  if (该掷了吗(今日.已生成于, 当前日期)) {
    const 新 = 掷一批(诊所等级, 随机);
    今日.待登记 = 新;
    // 昨天的申请单一并作废: 新的一天, 新的病人 (spec §9 从 AI 手上收回来的那件事)
    今日.申请列表 = {};
    // 昨天残留的报到同样不算数 —— 不挡的话, 新的一天会用今天的单子
    // 去配昨天那个人, 而今天的名单已经换了一批。
    今日.登场 = [];
    今日.已生成于 = 当前日期;
    return { 掷了: true, 新掷: 新.length, 晋级: [], 登场: [] };
  }

  // **顺序要紧: 先兼容回路, 后新路。**
  // 先老后新时, 处理登场 看到的 待登记 已经是 晋级已命名的 清理过的残表,
  // shift() 拿到的必然还没被用过 —— 顺手省掉一类重叠 bug。
  // 反过来也不错, 但过渡期 AI 两套都写时, 新路的 FIFO 可能撞上老路刚摘走的那张。
  const 晋级 = 晋级已命名的(今日);
  const 登场 = 处理登场(今日, 诊所等级, 随机);
  return { 掷了: false, 新掷: 0, 晋级, 登场 };
}
