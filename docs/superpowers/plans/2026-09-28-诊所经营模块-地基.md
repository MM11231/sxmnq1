# 诊所经营模块 · ① 地基 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把诊所经营的数值从 LLM 手上收回到前端 —— 申请列表由前端掷骰生成、诊金由前端定价、等级与床位由前端维护、结算改成可预测的加性。

**Architecture:** 新增 `src/sxmnq/生成/` 一层纯函数（池子数据 + 加权掷骰 + 闸门 + 定价），全部不依赖酒馆、可在 node 里直接跑测试；界面层只负责把这些纯函数的结果写进 MVU 变量。等级从七档合并为五档 `D/C/B/A/S`，`诊所.等级` 成为唯一真值。

**Tech Stack:** TypeScript + Vue 3 + zod + lodash + pinia；测试用 node 内置的 `.mjs` + 手写断言（沿用 `game.test.mjs` 的写法，本工程没有 vitest/jest）。Node v24.19.0，可直接 `import` `.ts`（类型擦除）。

**Spec:** `docs/superpowers/specs/2026-09-28-诊所经营模块-design.md`

## Global Constraints

- **等级只有五档**：`'D' | 'C' | 'B' | 'A' | 'S'`。`F` 与 `E` 在**任何地方**都不再出现。
- **等级值**：`{ D: 0, C: 1, B: 2, A: 3, S: 4 }`。
- **测试跑法**：`node <路径>.test.mjs`，退出码非 0 即失败。工程没有 vitest/jest，不要引入。
- **测试文件与被测文件同目录**，`.test.mjs` 后缀，用 `await import(new URL('./xxx.ts', import.meta.url).href)` 载入。
- **每个新建的 `.test.mjs` 都要 `import '<相对路径>/测试钩子.mjs';`**（Task 1 执行时补上的）。
  **放在 `/* eslint-disable */` 和文件头那段注释之后、第一个 `await import(...)` 之前** ——
  静态 import 一律提升，所以位置不影响行为，但这样读起来最顺（`schema.test.mjs` 就是这么排的）。
  源码里的相对导入**不带扩展名**（`from './分档'`）—— webpack 与 tsc 会自己补 `.ts`，
  **Node 的原生 ESM 解析器不会**，直接 `ERR_MODULE_NOT_FOUND`。
  另外 `schema.ts` 用的是裸 `z` / `_`，那是 webpack 的 auto-import 注入的，node 里没有。
  `src/sxmnq/测试钩子.mjs` 把这两件事一起办了（注册解析钩子 + 挂 `globalThis.z` / `_`），
  静态 import 会在测试主体之前求值，所以顺序天然是对的。
  路径按层级调整：`src/sxmnq/生成/x.test.mjs` 写 `'../测试钩子.mjs'`，
  `src/sxmnq/界面/状态栏/x.test.mjs` 写 `'../../测试钩子.mjs'`。
  **不要把它复制进测试文件** —— 那是五个文件五份拷贝。
- **`ts-loader` 是 `transpileOnly`**：枚举值写错**不会**在构建期报错。schema 的 `safeParse` 失败是**静默丢弃**（`util/mvu.ts` 里 `if (result.error) return`），界面上只表现为一片默认值。所以每次动 schema 都必须跑一遍假数据校验。
- **Vue 组件标签名必须是 ASCII**（`<TreatmentPanel />` 而不是 `<治疗面板 />`），`@keyframes` 名同理。非 ASCII 会被当纯文本，生产构建才发作且不报错。
- **只读**：`F:\桌面\[哨向]白塔.json` 是素材源，绝不修改。

### 测试文件的固定开头

下面每个任务给的 `.test.mjs` 代码块**都从 `/* eslint-disable */` 开始**，因为主体各不相同。
实际写文件时，`/* eslint-disable */` 之后要补上这一行再往下抄：

```js
import '../测试钩子.mjs';   // 层级按目录调整: 见 Global Constraints 那条
```

少了它，`node xxx.test.mjs` 会在**第一行 import 就炸**（`ERR_MODULE_NOT_FOUND`
或 `ReferenceError: z is not defined`），而不是报某个断言失败 —— 别把它当成逻辑写错了。

## 本次计划里做的两个判断（spec 没写死，实装时定的）

1. **`诊所.床位` 在 ① 就是一个真变量**（prefault `1`，即开局自带一张床）。
   spec §6.1 说床位最终来自家具（②商店）；但 ①1e 要有床位闸门，`§12` 的状态栏又要显示「床位占用 2/3」。若 ① 写死常量，② 就得再做一次 schema 迁移。所以 ① 先落成普通数字，② 再改成由 `摆位` 派生。

2. **`疗效` / `减耗` / `气氛` / `家具` / `摆位` 都不在 ① 里加**。
   `疗效` 与 `减耗` 在 ① 一律取 `0`（正是 spec §5.1 的公式原样），`气氛` 不显示。它们全是 ②③ 的产物，提前加字段等于给平衡留一堆没人写的接口。
   代价是 ② 要改 `算精神力消耗` 的实参 —— 那本来就是 ② 的活。
   `舒适描述` 相应地改成吃 `减耗`：`值 = (减耗 + 1) * 12 + 信赖 * 0.4`，在 `减耗 = 0` 时与原 `躺椅等级 = 1` **数值完全一致**，所以翻译文案不变。

```ts
/**
 * 掷骰 —— 把 池子.ts 里的表变成「掷一个具体的人」。
 *
 * **每个函数都收一个 随机源, 默认 Math.random。** 多这个参数就是为了能测:
 * 传一串写死的数进去, 结果就是确定的, 于是「同一个种子出同一个人」这句话
 * 才验得了。生产代码一个字都不用改 —— 不传就是 Math.random。
 *
 * 这一层不认识等级也不认识污染度 —— 那些是闸门(闸门.ts)的事,
 * 因为它们的取值范围取决于**玩家诊所的等级**, 而这里是纯粹的人物属性。
 */
import {
  个人特征池, 地域池, 地域纲系数, 危险权重, 体型权重, 性格A面, 性格B面,
  栖息权重, 年龄上限, 年龄下限, 纲方向, 纲权重,
} from './池子';

export type 随机源 = () => number;

/** 按权重抽一个键。权重不必归一 —— 内部自己求和 */
export function 加权抽(池: Record<string, number>, 随机: 随机源 = Math.random): string {
  let 总 = 0;
  for (const k in 池) 总 += 池[k];
  let r = 随机() * 总;
  for (const k in 池) {
    r -= 池[k];
    if (r < 0) return k;
  }
  // 浮点误差导致 r 掉不进去时的兜底
  return Object.keys(池)[0];
}

/** 等概率抽一个 */
export function 均匀抽<T>(表: readonly T[], 随机: 随机源 = Math.random): T {
  return 表[Math.floor(随机() * 表.length)];
}

/** 闭区间整数 —— 上下限都取得到 */
export function 掷区间(下限: number, 上限: number, 随机: 随机源 = Math.random): number {
  return 下限 + Math.floor(随机() * (上限 - 下限 + 1));
}

/**
 * 纲的权重池, 已乘上地域系数。**不归一** —— 归一在这里没有意义,
 * 加权抽自己会求和。导出它是为了让它可测: 系数有没有乘上去, 看这个函数就够了。
 */
export function 算纲池(地域: string): Record<string, number> {
  const 地域键 = 取地域键(地域);
  const 系数 = 地域纲系数[地域键] ?? {};
  const 池: Record<string, number> = {};
  for (const 纲 in 纲权重) 池[纲] = 纲权重[纲] * (系数[纲] ?? 1);
  return 池;
}

/** 从 地域池 那条带描述的长串里认出是哪个地域。认不出返回空串, 系数就当全 1 */
function 取地域键(地域: string): string {
  for (const 键 of Object.keys(地域纲系数)) {
    if (地域.includes(键)) return 键;
  }
  return '';
}

export function 掷地域(随机: 随机源 = Math.random): string {
  return 均匀抽(地域池, 随机);
}

export interface 精神体 {
  /** 纲。AI 要在这个方向里自己推一个具体物种 */
  纲: string;
  /** 交给 AI 的选种范围提示 */
  方向: string;
  栖息: string;
  体型: string;
  危险: string;
}

/**
 * 掷精神体。**先掷纲, 后三样都从纲对应的那一行里抽** ——
 * 这个联动是白塔那套的灵魂: 掷到鸟纲就不可能得到「穴居」占 30% 的结果。
 */
export function 掷精神体(地域: string, 随机: 随机源 = Math.random): 精神体 {
  const 纲 = 加权抽(算纲池(地域), 随机);
  return {
    纲,
    方向: 纲方向[纲],
    栖息: 加权抽(栖息权重[纲], 随机),
    体型: 加权抽(体型权重[纲], 随机),
    危险: 加权抽(危险权重[纲], 随机),
  };
}

const 特征池名 = Object.keys(个人特征池) as (keyof typeof 个人特征池)[];

/**
 * 掷 1~2 个人特征, **必须来自不同的池** ——
 * 「泪痣 + 雀斑」是两张脸挤在一起, 「泪痣 + 药味」才是一个人。
 * 白塔原文是把四个池洗牌后取前 N 个, 这里换成 Fisher-Yates —— 顺手, 且可测。
 */
export function 掷个人特征(随机: 随机源 = Math.random): string[] {
  const 池们 = [...特征池名];
  for (let i = 池们.length - 1; i > 0; i--) {
    const j = Math.floor(随机() * (i + 1));
    [池们[i], 池们[j]] = [池们[j], 池们[i]];
  }
  const 个数 = 掷区间(1, 2, 随机);
  return 池们.slice(0, 个数).map(名 => 均匀抽(个人特征池[名], 随机));
}

export function 掷性格(随机: 随机源 = Math.random): { A面: string; B面: string } {
  return { A面: 均匀抽(性格A面, 随机), B面: 均匀抽(性格B面, 随机) };
}

export function 掷年龄(随机: 随机源 = Math.random): number {
  return 掷区间(年龄下限, 年龄上限, 随机);
}

export interface 命名要求 {
  /** 名字要几个字, 2~4 */
  字数: number;
  /** 中式姓名还是西式音译名。**4 字时恒为 false** —— 白塔原文: 4 字强制西式 */
  中式: boolean;
}

/**
 * 名字的字数与中外, 由代码掷; 具体叫什么, 由 AI 写 (spec §8.2)。
 *
 * 4 字以上强制西式音译, 是因为四字中式会滑向复姓与化用名 ——
 * 那正是白塔的命名法则要躲开的东西。
 */
export function 掷命名要求(随机: 随机源 = Math.random): 命名要求 {
  const 字数 = 掷区间(2, 4, 随机);
  return { 字数, 中式: 字数 < 4 && 随机() < 0.5 };
}
```

```ts
/**
 * 闸门 —— 谁会来这家诊所。
 *
 * **闸门管的是概率分布, 不是准入名单**（spec §4 开头那句）。
 * D 级诊所不是「不让 B 级病人进门」, 是「B 级病人压根不会听说你」。
 *
 * 与 掷骰.ts 的分界: 掷骰掷的是「这个人长什么样」, 跟玩家无关;
 * 这里掷的每一项都取决于**玩家诊所的等级**。所以掷骰不认识等级, 这里认识。
 */
import { 等级序, 等级值, type 等级 } from '../等级';
import { 加权抽, 掷区间, type 随机源 } from './掷骰';

/** 能收到的哨兵等级: 从 D 起, 到诊所等级 +1 止。低等级永远能来, 每升一档解锁高它一档的客人 */
export function 可来等级(诊所等级: 等级): 等级[] {
  return 等级序.slice(0, Math.min(等级值[诊所等级] + 2, 等级序.length));
}

/**
 * 权重: 本档 3, 每低一档 −1, 下限 1; 高一档恒为 1。
 *
 * 读法 —— **多数是同级的, 其次是低一级的, 高一级的是稀客。**
 * 低档从 3 递减到 1 就停住 (不再继续降), 否则 S 级诊所的池子里
 * D 级客人的权重会变成 −1, 加权抽直接崩。
 */
export function 闸门权重(诊所等级: 等级, 目标: 等级): number {
  const 差 = 等级值[诊所等级] - 等级值[目标];
  if (差 < 0) return 1; // 高一级的稀客
  return Math.max(1, 3 - 差);
}

export function 掷等级(诊所等级: 等级, 随机: 随机源 = Math.random): 等级 {
  const 池: Record<string, number> = {};
  for (const 目标 of 可来等级(诊所等级)) 池[目标] = 闸门权重(诊所等级, 目标);
  return 加权抽(池, 随机) as 等级;
}

/**
 * 污染度区间 —— **难度差异的真正来源**。
 *
 * spec §3.4 把等级差锁死在 [−1, +1] 之后, 等级本身已经带不来多少难度变化了;
 * 同一个 D 级病人可以污染 20 也可以是 45, 那才是这一单要跑几趟的原因。
 */
export const 污染度区间: Record<等级, [number, number]> = {
  D: [20, 45],
  C: [35, 65],
  B: [55, 85],
  A: [70, 95],
  S: [85, 100],
};

export function 掷污染度(等级: 等级, 随机: 随机源 = Math.random): number {
  const [低, 高] = 污染度区间[等级];
  return 掷区间(低, 高, 随机);
}

/** 基础诊金 —— 病人卡上显示的就是它。结算时才乘评级系数 */
export function 算基础诊金(等级: 等级, 污染度: number): number {
  return (等级值[等级] + 1) * 40 + 污染度 * 2;
}

/**
 * 实际诊金 = 基础 × 评级系数。
 *
 * 单独一个函数而不是写在结算里, 是为了让「系数不该出现在 申请列表 上」
 * 这件事有个明确的位置可指 —— 定价发生在接诊之前, 系数在接诊之后才知道。
 */
export function 算实际诊金(基础诊金: number, 评级系数: number): number {
  return Math.round(基础诊金 * 评级系数);
}

## Task 6: 日期戳与流转（1d）

spec §8.3 / §8.4 / §8.5 的那套流转。**这一层的全部难点是一个词：幂等。**

状态栏 iframe 每次渲染消息都会重建，掷骰逻辑在里面跑。没有防护的话，玩家每发一条消息就多来一批病人。解法是 `今日.已生成于` 这个日期戳：**只要戳等于 `世界.日期`，就什么都不做**，无论这段代码被跑多少次。

> **与 spec §8.5 的一处偏离，先说清楚。**
> §8.5 写的是「AI 逐一命名后，整体写入 `/今日/申请列表/`、清空 `/今日/待登记/`」。
> 本计划改成：**AI 只写 `待登记[i].姓名` 与 `待登记[i].战损来源` 两个字段，晋级的活由前端干。**
> 理由是这个模块存在的全部意义（spec §9）就是**别让 AI 转抄数字**。照 §8.5 原样做，AI 每回合要把等级、污染度、诊金、年龄、地域、精神体四属性、特征、A/B 面逐字抄进 `申请列表` —— 一个人十几个字段，一批三到六个人。抄漏一个，zod 的 `prefault` 会**静默**填上默认值，于是那个病人的诊金变成 0，而界面上什么都不报。
> 改后 AI 只需要在两个已知的格子里填字符串，**没有任何数字要它经手**；§8.5 真正想要的那件事（不用逐个匹配姓名，一次给全）一个字都没丢。

**Files:**
- Create: `src/sxmnq/生成/流转.ts`
- Test: `src/sxmnq/生成/流转.test.mjs`

**Interfaces:**
- Consumes: `生成.ts` 的 `待登记条目` / `掷一批` / `每日人数下限` / `每日人数上限`；`等级.ts` 的 `type 等级`
- Produces:
  - `interface 申请条目`（档案字段 + `状态`）
  - `interface 今日数据 { 已生成于: string; 待登记: 待登记条目[]; 申请列表: Record<string, 申请条目> }`
  - `interface 流转结果 { 掷了: boolean; 新掷: number; 晋级: string[] }`
  - `function 该掷了吗(已生成于: string, 当前日期: string): boolean`
  - `function 晋级已命名的(今日: 今日数据): string[]`（**就地改**）
  - `function 跑一次(今日: 今日数据, 当前日期: string, 诊所等级: 等级, 随机?: 随机源): 流转结果`（**就地改**）

> **这两个函数就地改传入的对象，不返回新对象** —— 和 `应用结算` 一个路子（详见 `结算.ts` 末尾那段注释：store 会在下一拍把整份数据重新 parse 一遍）。传进去的是 pinia 里的 reactive 代理，就地改才会触发界面更新。

/**
 * 流转 —— 掷完的人怎么变成正式的申请者。
 *
 *   待登记[i]   ← 前端掷 (生成.ts)。有数值, 没名字, 界面上显示「未登记 · 01」
 *       │
 *       │  AI 写 姓名 + 战损来源  (spec §8.2: 名字归 AI, 因为它有审美)
 *       ▼
 *   申请列表[姓名]  ← 玩家点接诊
 *       │
 *       ▼
 *   哨兵[姓名]      ← 在诊(占床) → 已出院 / 已收编
 *
 * **这个文件里最要紧的一个词是「幂等」。**
 * 状态栏 iframe 每次渲染消息都会重建, 跑一次() 会被调用很多次。
 * 唯一挡住重复掷骰的是 今日.已生成于 这个日期戳 —— 见 spec §8.4。
 *
 * 与 spec §8.5 的一处偏离 (AI 只写两个字段, 晋级由前端干) 记在实施计划里。
 */
import type { 等级 } from '../等级';
import { 掷一批, type 待登记条目, type 精神体掷定值 } from './生成';
import type { 随机源 } from './掷骰';

/** 进了申请列表的哨兵。少了 字数/中式 (那是给 AI 下命名指令用的), 多了 状态 */
export interface 申请条目 {
  等级: 等级;
  污染度: number;
  诊金: number;
  年龄: number;
  地域: string;
  精神体: 精神体掷定值;
  特征: string[];
  A面: string;
  B面: string;
  战损来源: string;
  状态: string;
}

export interface 今日数据 {
  已生成于: string;
  待登记: 待登记条目[];
  申请列表: Record<string, 申请条目>;
}

export interface 流转结果 {
  掷了: boolean;
  新掷: number;
  晋级: string[];
}

/**
 * 今天掷过没有。**`当前日期` 为空时一律返回 false。**
 *
 * 那个空判断是必须的: 存档刚开、AI 还没写第一句话的时候 世界.日期 是空串,
 * 而 已生成于 的初始值也是空串 —— 不挡住的话, 开局第一帧就会掷一批,
 * 抢在 AI 写日期之前。等到 AI 真写了日期, 戳对不上, 又掷一批。
 * 玩家会在还没开张的诊所里看到两批病人。
 */
export function 该掷了吗(已生成于: string, 当前日期: string): boolean {
  return 当前日期 !== '' && 已生成于 !== 当前日期;
}

/**
 * 把已经有名字的从 待登记 摘进 申请列表。**就地改 今日。**
 *
 * 没有名字的原地留下 —— 不需要逐个匹配, AI 写在哪个槽里就是哪个 (spec §8.5)。
 */
export function 晋级已命名的(今日: 今日数据): string[] {
  const 晋级: string[] = [];
  const 留下: 待登记条目[] = [];

  for (const 条 of 今日.待登记) {
    const 名 = (条.姓名 ?? '').trim();
    if (!名) {
      留下.push(条);
      continue;
    }
    // 逐字段搬, 不用展开语法 —— 这样 字数/中式 与 姓名 自然就被挡在外面,
    // 且以后 待登记条目 加字段时这里会**编译不过**, 而不是静默漏掉。
    今日.申请列表[名] = {
      等级: 条.等级,
      污染度: 条.污染度,
      诊金: 条.诊金,
      年龄: 条.年龄,
      地域: 条.地域,
      精神体: 条.精神体,
      特征: 条.特征,
      A面: 条.A面,
      B面: 条.B面,
      战损来源: 条.战损来源,
      状态: '待接',
    };
    晋级.push(名);
  }

  今日.待登记 = 留下;
  return 晋级;
}

/**
 * 状态栏挂载时、以及 世界.日期 一变时调这个。**就地改 今日。**
 *
 * 顺序很要紧: **先看日期戳, 再谈晋级。**
 * 反过来的话, 昨天掷的、AI 忘了命名的那些人会被晋级进今天的申请列表 ——
 * 而今天的名单已经换了一批人了。
 */
export function 跑一次(
  今日: 今日数据,
  当前日期: string,
  诊所等级: 等级,
  随机: 随机源 = Math.random,
): 流转结果 {
  if (该掷了吗(今日.已生成于, 当前日期)) {
    const 新 = 掷一批(诊所等级, 随机);
    今日.待登记 = 新;
    // 昨天的申请单一并作废: 新的一天, 新的病人 (spec §9 从 AI 手上收回来的那件事)
    今日.申请列表 = {};
    今日.已生成于 = 当前日期;
    return { 掷了: true, 新掷: 新.length, 晋级: [] };
  }

  return { 掷了: false, 新掷: 0, 晋级: 晋级已命名的(今日) };
}

## Task 7: 结算改加性，治疗次数与床位上桌（1e）

前三步让「有病人来」成立了，这一步让「治得完」成立。

三处改动，spec §5 的：

2. **`单次清除量` 只跟诊所等级走**（§5.1），与病人等级无关
3. **`预计次数` 上病人卡，每人在诊占一张床**（§5.2）

> **⚠ 发现一处 spec 自相矛盾，这里按 §4.3 走。**
> §4.3 说「实际诊金 = round(基础诊金 × 评级系数)，S 1.5 / A 1.2 / B 1.0 / C 0.8」，并明说「**评级系数沿用现有 `结算.ts` 的 `收益表`**」。
> §5.3 说「把 `收益表.污染降幅` 换成 `评级系数`」，紧接着给了一张**数字不一样**的表：`S 1.2 / A 1.0 / B 0.8 / C 0.5`，但它的正文同样写着「沿用」。
> **用一个系数**（1.5/1.2/1.0/0.8）是唯一自洽的读法：spec 两处都管它叫`评级系数`，两处都说「沿用」，而且「评级同时决定诊金和清除量」本来就是 §5.3 那句「评级第一次有了数值后果之外的意义」的意思。

 * 「什么时候该掷」是一条有幂等要求的规则 (spec §8.4), 值得有自己的注释和位置,
 * 而不是散在组件的 setup 里。
 */
import { watch } from 'vue';
import type { 等级 } from '../../等级';
import { 跑一次, type 今日数据 } from '../../生成/流转';

export interface 接线源 {
  /** 今日那一块 —— 注意要传 store 上的那个 reactive 对象, 不要传副本 */
  今日: () => 今日数据;
  /** 读 世界.日期。AI 写, 前端只读 (spec §9) */
  日期: () => string;
  /** 诊所当前等级 —— 掷骰的概率池由它决定 */
  等级: () => 等级;
}

/**
 * 盯住 世界.日期: 变了就重掷一批, 没变就只把 AI 命好名的人晋级。
 *
 * `immediate: true` 是必须的 —— 挂载的那一刻也得跑一次,
 * 否则玩家刷新页面之后, 昨天掷好的一批人永远晋级不了。
 *
 * **不需要防抖**: 跑一次() 本身是幂等的 (去看 流转.test.mjs 里
 * 「连跑 20 次仍然只有一批」那一段), 重复触发只会白跑一遍。
 */
export function 盯住日期(源: 接线源) {
  return watch(
    () => [源.日期(), 源.等级()] as const,
    ([日期]) => {
      跑一次(源.今日(), 日期, 源.等级());
    },
    { immediate: true },
  );
}
```

> `等级` 也在 watch 的来源里：诊所升级之后概率池会变宽，但**已经掷好的那批人不会重掷**（日期戳还是今天），所以这条 watch 只影响下一天。这正是想要的行为 —— 升完级当天就换一批客人，玩家会以为自己眼花了。
