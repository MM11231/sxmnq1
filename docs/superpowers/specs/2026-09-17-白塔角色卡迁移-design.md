## 1. 背景

「[哨向]白塔」是一张已完成并持续迭代（v3.2.2）的哨向题材角色卡，目前以**打包产物**的形式存在——单个 855KB 的 JSON。这个形态带来三个问题：

1. **无法维护**：112 条世界书条目、4 段共 194KB 的 HTML、3 段内联脚本全部塞在一个 JSON 里，任何修改都要在 7,149 行中定位。
2. **无法热重载**：改 UI 必须改正则替换串 → 重新导入卡 → 重开聊天，反馈循环极长。
3. **无法版本化**：diff 就是整个文件，看不出改了什么。

`tavern_helper_template` 提供的正是这条缺失的链路：YAML/TS 源码 → webpack 构建 → `dist/` → jsdelivr CDN → 酒馆运行时加载。

## 2. 目标与非目标

### 目标

- 把卡的全部内容（世界书、正则、脚本、开场白、元数据）迁入可维护的源码结构
- 建立「源码 → 构建 → CDN → 酒馆」的自动发布链路（GitHub Actions）
- 4 段 UI 从正则替换串搬进 `src/`，正则退化为一行 loader
- 补齐当前为空的元数据字段
- 清理死数据

### 非目标（明确不做）

- ❌ 把 UI 重写成 Vue 组件 —— 本次「原样搬出」，重构留作第二阶段
- ❌ 修改 112 条条目的 `exclude_recursion` / `prevent_recursion`（用户确认保留现状）
- ❌ 去除 EJS 扩展依赖（用户确认继续依赖）
- ❌ 重构 `ITEM` 脚本基于 uid 的条目定位机制
- ❌ 改动任何条目内容语义

### 3.3 🔴 高危：`id`/`uid` 陷阱

`ITEM` 脚本（20,460 字符）通过 **uid 数值**定位条目，控制「白塔组 / 校园组 / 极南组」的开关，共 **67 处引用**，范围 2–137。

**这 67 个引用全部能在 `entries[].id` 中找到，无一悬空。** 但条目只有 `id`，**没有 `uid` 字段（0/112）**。

> **风险**：迁移过程中若按数组下标重新编号，67 处引用全部错位，三个 DLC 的条目开关静默失效——不报错，只是该开的没开、该关的没关。
>
> **约束**：迁移必须原样保留 `id` 数值，或显式重建映射表。`tavern_sync` 的 YAML schema 支持 `uid` 字段，走 `pull` 路线时由酒馆侧提供，天然正确。

### 3.4 🟡 IDX 18 的 comment 内嵌换行

| idx | 字符码点 | 原文 |
|---|---|---|
| 18 | `…21551,8212,10,69,74,83…` | `固定开启—␊EJS-污染度` |

`固定开启—` 后紧跟一个裸 LF，再接 `EJS-污染度`。该条目 `enabled=True, constant=True`，是活跃常驻条目。

> **影响**：`tavern_sync pull` 用条目名生成文件名，裸换行在 Windows 文件系统上会导致失败。
>
> **处理**：M0 阶段在酒馆里改名为 `固定开启—EJS-污染度`。**零功能影响**——`ITEM` 按 uid 定位不看名字，`DLC` 按 `CH01`~`CH04` 匹配不涉及此条。

### 3.5 🔴 高危：顶层 `position` 与 `extensions.position` 矛盾

顶层 `position`（字符串）只有 2 个取值，把一个本有 4 种语义的字段压平了：

| 顶层 position | extensions.position | depth | 条数 |
|---|---|---|---|
| `before_char` | 0 | 4 | 25 |
| `after_char` | 1 | 4 | 74 |
| `after_char` | **2** | 4 | **1** |
| `after_char` | **4** | 4 | **8** |
| `after_char` | **4** | 3 | **1** |
| `after_char` | **4** | 0 | **3** |

> **结论**：`extensions.position`（数值）是权威值；顶层 `position` 是遗留的有损降级表示。只读字符串字段的导入器会让 **13 条条目定位错误**（12 条 at-depth + 1 条 AN-top）。
>
> **约束**：迁移以 `extensions.position` + `extensions.depth` 为准。

`depth` 取值与 `position` 语义脱节：108 条带 `depth=4`，但其中仅 8 条真正是 at-depth。真正生效的是 12 条 `position=4`：`depth=4`×8、`depth=0`×3、`depth=3`×1。

### 4.2 构建管线（已验证）

- **入口发现**：`fs.globSync('{示例,src}/**/index.{ts,tsx,js,jsx}')` —— 只有名为 `index.ts/tsx/js/jsx` 的文件是入口
- **嵌套折叠**：入口目录若为另一入口目录的祖先，只保留最外层
- **界面 vs 脚本判据**：入口同级目录**是否有 `index.html`**。有 → 前端界面，JS/CSS 全部内联进单个 HTML；无 → 脚本，输出单文件 ESM `index.js`
- **路径映射**：`dist/{入口路径去掉第一段}/`。即 `src/白塔/界面/社畜向导/index.ts` → `dist/白塔/界面/社畜向导/index.html`
- **externals**：`jquery/lodash/toastr/vue/vue-router/yaml/zod/showdown` 映射为酒馆网页全局变量

### 4.3 发布链路

```
src/ → pnpm build → dist/ → git push → GitHub Actions (bundle.yaml)
    → 自动重新构建 + 打版本 tag → jsdelivr CDN
    → 酒馆运行时按 URL 加载
```

URL 形态：
- 界面：`https://testingcf.jsdelivr.net/gh/<user>/<repo>/dist/白塔/界面/社畜向导/index.html`
- 脚本：`https://testingcf.jsdelivr.net/gh/<user>/<repo>/dist/白塔/脚本/条目控制/index.js`

### 4.4 正则的形态变化

**迁移前**（以 #4 为例）：
```
查找表达式: <StatusPlaceHolderImpl/>
内容: ```
      <html>…95,806 字符的内联 HTML…</html>
      ```
```

**迁移后**：
```
查找表达式: <StatusPlaceHolderImpl/>
内容: ```

      <script>
      $('body').load('https://testingcf.jsdelivr.net/gh/<user>/<repo>/dist/白塔/界面/社畜向导/index.html')
      </script>
      </body>
      ```
```

3 条擦除型正则（#0/#1/#2）形态不变。

### 4.5 界面内部的代码拆分

每段 HTML 拆成两个文件：

- `index.html` ← 原 `<style>` + 标记结构
- `index.ts` ← 原内联 `<script>` 的内容，包成 ES 模块

> ⚠️ **风险**：脚本从 `<script>` 搬进 `index.ts` 后，顶层声明的作用域从**全局**变为**模块**。若 HTML 内存在 `onclick="fn()"` 之类依赖全局的引用，会静默失效。
>
> **缓解**：搬迁前先枚举 4 段脚本的所有顶层声明，与 HTML 中的事件属性引用做交叉核对，必要时显式挂到 `window`。

### 7.1 落位路径的约束与处置

用户要求工程放在酒馆目录内以便预览。实测发现：

- `D:\game1\SillyTavern` **本身是一个 git 仓库**，`origin = https://github.com/SillyTavern/SillyTavern`，分支 `release`。工程若直接摊在根目录，源文件会出现在酒馆仓库的 `git status` 中，存在被误 `git add -A` 提交进上游仓库的风险。
- 处置：工程置于子目录 `白塔卡源/`，并在 `D:\game1\SillyTavern\.git\info\exclude` 中追加 `白塔卡源/`。
  - 之所以用 `.git/info/exclude` 而非 `.gitignore`：前者是**纯本地**忽略，不改动酒馆仓库的受版本控制文件，酒馆 `git pull` 升级时不会产生冲突。
  - 实测 `git check-ignore` 命中，且酒馆仓库 `git status --porcelain` 为 0 项，隔离生效。
- 酒馆更新脚本 `UpdateAndStart.bat` 仅执行 `git pull --rebase --autostash`，**不含 `git clean` / `git reset --hard`**，不会删除该子目录。
- 该位置不在 `public/`（不被 HTTP 静态服务）、不在 `data/`（不被识别为用户目录）、不是酒馆已知子目录，不会被酒馆扫描或纳入聊天备份。

### 7.2 `.vscode/launch.json` 核查结论

模板 README 警告该文件"填写了你的酒馆地址，公开仓库前需 `git update-index --skip-worktree`"。
**实测内容为 `http://localhost:8000`（本机地址，非云酒馆 IP）**，不存在地址泄露问题，可随仓库公开，无需 `skip-worktree`。
该端口与 `D:\game1\SillyTavern\config.yaml` 中的 `port: 8000` 一致。
