# 哨向模拟器 · 家园与家具设计

> 本文件是《诊所经营模块设计》（`2026-09-28-诊所经营模块-design.md`，下称**前序**）的
> **第一个子项目设计**。前序把整个经营模块拆成了四步，本文件覆盖其中的 ①，
> 并对前序的若干条做出修订 —— 修订处一律在 §2 集中列出。

---

## 1. 一句话

**把「买家具」和「摆家具」合成一件事：点九宫格里的格子，商店就在那里出现。**

---

## 2. 本文件修订了前序的什么

### 2.1 删掉 `减耗` 与 `疗效` —— 效果字段从四个变两个

用户原话：「**不需要有减耗和疗效这种效果。**」

前序 §6.1 定义了四个效果字段：`床位` / `疗效` / `减耗` / `氛围`。现在只剩**两个**，
`疗效` 和 `减耗` 连同为它们而设的 `设施` 类型一起消失。

**这一条是「删已上线的代码」，不是纯新增。** 好在这两个字段目前都是空转的：

- `减耗` 在 ① 地基里**恒为 0**（`治疗/game.ts:35` 的注释自己写着），删它是**行为不变**的重构
- `疗效` 从来没有任何一处读过它（全项目 grep 只有前序文档里提到）

### 2.2 「商店」不再是一个界面

前序 §6.2 把商店列为一张界面（§12 的界面表里也是一行）。**现在没有商店这个界面了** ——
商店是**格子的弹层**：点一个格子，弹层里同时是「这里能放什么」和「这里能买什么」。

前序 §13 执行顺序里的「② 商店 → ③ 装修」两步因此合并。

### 2.3 「不另做居住」正式作废

前序 §6.3 的条款：

> **不另做**居住 / 分房 / 「谁住哪间」那一层 —— 「谁住哪」是极南的概念，本卡不做。

**作废。** 用户 **2026-09-28** 明确推翻：「我直接在诊疗室固定的几个地方设置为床位区块」
「未来哨兵住进来」「房间可以给哨兵住」。

原 §15 待定 #4 因此升格成**独立的子项目 ③ 居住**。

### 2.4 床位从「一个数」变成「房间里摆了几张床」

前序 §11 的 `诊所.床位` 是个数字（`prefault(1)`，注释写「开局自带一张床」）。
现在它是**派生值** —— 几个房间里实际摆了床。

## 3. 三层结构

用户原话：「家这个第一次可以是总览，我们点击诊室的格子进入第二层可以有五个房间。
点击房间可以有一个九宫格，里面固定有一张床，和几个自由模块可供玩家装饰。」

```
L1  家 · 总览          [诊所][大门][杂物间][虚线…]
        │  点「诊所」
        ▼
L2  诊所 · 五个房间     一号  二号  三号
        （3×3）        路    路    路
                       四号  门    五号
        │  点一间房
        ▼
L3  一间房 · 2×3       自由  床    自由
        （3×3 外框）    自由  门    自由
                       灰    灰    灰        ← 只占位，不可点
```

| 层 | 内容 | 本子项目 |
|---|---|---|
| **L1 家·总览** | 诊所 / 大门（信箱）/ 杂物间（仓库）/ 虚线空格 | **不做**（留给 ②） |
| **L2 诊所·五个房间** | 5 个房间 + 1 扇门 + 3 格路 | **做** |
| **L3 一间房** | 4 个自由格 + 1 张床 + 1 扇门 + 3 格灰 | **做** |

### 3.1 为什么 ① 必须吃下 L2

**因为不吃下它，床位永远卡在 1。** 五个床位住在 L2 的五个房间里；只做 L3 就只有一号房，
**第二张床没有地方摆**。而前序 §5.2 的整个「住院占床」机制在床位 1 的时候等于不存在
—— 同时只能治一个病人，`没床了` 永远不出现。

所以 ① 交付的是**完整可玩的诊所**：床位 1→5 靠买床填满五间房，数值全通。

### 3.2 2 只做 L1

L1（家的总览、大门/信箱、杂物间/仓库）是**纯导航 + 两个尚未设计的子系统**，
放在 ① 做完、诊所本身能玩了之后再说。

## 4. 九宫格组件

**三层共用同一个组件**，喂不同的数据。这是把 L2 放进 ① 而不是 ② 的关键
—— L2 和 L3 不是两套东西，是同一个组件的两份数据。

### 4.1 格子种类与颜色

用户原话：「**床用蓝色，门用黄色，自由用绿色，路和不能用的统一用灰色表示就行。**」

| 格类 | 颜色 | 可点 | 行为 |
|---|---|---|---|
| **床** | 蓝 `#7fe3ff` | 是 | 空着 → 买床；有床 → 换更好的床 / 收起来 |
| **自由** | 绿 `#7fd6a0` | 是 | 摆装饰 / 换成别的装饰 / 收起来 |
| **门** | 黄 `#ffd76e` | 是 | 返回上一层（见 §4.3） |
| **路** | 灰 `rgba(255,255,255,0.05)` | **否** | 纯占位，没有任何交互 |
| **房间** | 卡片样式 | 是 | 只有 L2 有；点它下钻到 L3 |

> **「路」和「灰」是同一件事**：L3 下排那三格点不动的，就是「路」。
> 用户原话：「一个房间不可能九个模块都塞满了东西」「少的那 3 个可以用灰色暗示」。

颜色落在**边框 + 约 10% 透明度的底色**上，不是整格铺满 —— 九格全铺满会太吵。

`房间` 那一类用户没给颜色，沿用现有卡片样式（边框 + 名称 + `▶`）。若之后要颜色，加一个即可。

### 4.2 两层各自的房型图

房型图是**代码常量**，不是变量 —— 一层的地形是写死的，玩家改不动它。

**L2 · 诊所的五个房间**（用户原话：「四号和五号往下一格」）：

```ts
西北 一号    北 二号    东北 三号
西   路      中 路      东   路
西南 四号    南 门      东南 五号
```

上排三间、下排两间夹着门、**中间一整条横向过道**。

**L3 · 一间房**（用户原话：「可以变成 2*3 的六宫格。床和门在中间。少的那 3 个可以用灰色暗示」）：

```ts
西北 自由    北 床      东北 自由
西   自由    中 门      东   自由
西南 路      南 路      东南 路
```

九宫格的**外框三层保持一致**，但只有该实的地方是实的：**6 格实的 + 3 格灰的**。
床和门都在中列（北 / 中）。

### 4.3 门与返回

`门` 的行为是**「上一层」**，而组件收的是**一个回调**，不是写死的目标：

| 位置 | ① 里回哪 | ② 做完后 |
|---|---|---|
| L3 的门 | 回 L2 | 不变 |
| L2 的门 | **收起家园块，回正文**（① 里 L2 就是根） | 回 L1 |

所以 ② 只是把 L2 那个回调从「收起」改成「回 L1」—— **不是返工**。

## 5. 商店 = 格子的弹层

点任意一个「床」或「自由」格，弹出**该格的面板**。面板里分两段：

| 段 | 内容 |
|---|---|
| **这里能放的** | 仓库里类型匹配的家具，点一下即摆上 |
| **这里能买的** | 物品表里类型匹配的家具，显示价钱；钱不够则置灰并写明 |

规则：

- **从这里买 → 直接摆进这个格子。** 买和摆是一件事，不要求先去仓库取
- 格子已被占用时，不列「能买的」，改列 **`换成：<更好的同类>`** 与 **`收起来`**
- **`收起来` = 退回仓库**，不是卖掉。换下来的旧床退回仓库后，可以摆进另一间空房
  —— 于是「给一号房换诊疗床」顺带给了二号房一张折叠床
- 类型不匹配的物品**根本不列出来**（床格不显示装饰，反之亦然）

## 6. 物品

### 6.1 床

床**同时给床位和氛围**。前序 §6.1 那条「一件物品只有一个效果字段非零」**作废** ——
它是为了让定价好算，现在床两项都给，反而更好懂：**换更好的床 = 房间更舒服**。

| 物品 | 床位 | 氛围 | 价钱 |
|---|---|---|---|
| 折叠床 | +1 | +10 | 300 |
| 单人床 | +1 | +25 | 700 |
| 诊疗床 | +1 | +45 | 1400 |

用户原话：「商店就有比如**购买床，升级床（提升氛围效果）**这种」——
用户选了**「换更好的床」而不是「床有自己的等级」**：床就是名字，没有等级字段。

### 6.2 装饰

| 物品 | 氛围 | 价钱 |
|---|---|---|
| 素色窗帘 | +8 | 60 |
| 旧书架 | +12 | 100 |
| 助眠香薰 | +15 | 120 |
| 诊疗躺椅 | +10 | 150 |
| 恒温灯 | +12 | 180 |

前序商店表里的 `诊疗躺椅`（原 `减耗 +1`）和 `恒温灯`（原 `疗效 +2`）**保留，降级成装饰**
—— 现成的好物件，删了可惜。

**价钱与数值待调**（前序 §15 待定 #1），先给保守值。定价原则沿用前序：一件功能家具
≈ 3–5 场 D 级治疗的收入。

### 6.3 仓库

**仓库 = 买了但没摆的家具。** 它由两个来源产生：

1. 从一个格子里 `收起来`
2. 换床时退下来的旧床

「家园」按钮上的角标就是这个数。前序 §6.3 说的「仓库里有 N 件没摆」保持不变，
只是现在**买的时候不会先进仓库**（§5 的规则）。

## 7. 数值接线

### 7.1 床位（派生）

```
床位 = 家具 里「已摆放」且「类型 = 床」的件数
```

它不再是存储字段。前序 §5.2 的床位闸门（`能接诊吗`）逻辑不变，只是入参从写死的数字
变成了这个派生值。

### 7.2 气氛（派生）

```
气氛 = Σ 已摆放家具的 氛围          （未摆放的不算；本身不封顶）
信赖加成 = min(5, floor(气氛 ÷ 20))  ← 硬上限 +5，同前序 §7
```

**前序 §7 的量级估算要更新。** 前序写的是「一层七格自由格摆满约 +70~100 —— 刚好够到 +5
的天花板」，那是按**只有装饰产气氛**算的。现在床也产气氛，实际路径是：

```
开局 1 张折叠床                         10   → +0
＋素色窗帘 8 ＋旧书架 12 ＋助眠香薰 15    45   → +2
＋第二张折叠床                          55   → +2
＋两张换单人床（各 +15）                 85   → +4
＋换诊疗床                              125   → +5 吃满
```

是一条**很长的爬坡**，每一档都要几百金。**数值不用改**，只是前序那句话的算术依据换了。

### 7.3 `舒适描述` 重写 —— 这是删 `减耗` 带出的唯一公式改动

现状（`界面/状态栏/结算.ts:101`）：

```ts
const 值 = (减耗 + 1) * 12 + 信赖 * 0.4;   // 档位 20 / 40 / 60 / 80
```

`(减耗 + 1) * 12` 那一项，注释自己写明是替旧的 `躺椅等级 × 12` —— 它**本来就是
「诊所好不好」的代称**。减耗一删，最高档直接够不着（信赖最多贡献 40 分）。

**改成 `气氛`，基准 12 原样保留：**

```ts
export function 舒适描述(气氛: number, 信赖: number): string {
  const 值 = 12 + (气氛 + 信赖) * 0.4;
  ...
}
```

验算：

| 气氛 | 信赖 | 值 | 档位 |
|---|---|---|---|
| 0 | 0 | 12 | 很不自在 ← **与改动前逐字一致** |
| 0 | 100 | 52 | 还算安稳 ← 同上 |
| 70 | 100 | 80 | 敞开（满装修 + 满信赖） |
| 170 | 0 | 80 | 敞开（光靠装修也够得着） |

**顺手多了一个好处**：装修从此有**两个**回报 —— §7.2 的信赖加成 +5，和这段结算文案。
而且最高档变成「装修**和**感情都要」，正好是这句话该有的分量。

### 7.4 `算精神力消耗` 简化

```ts
// 旧
export function 算精神力消耗(线数: number, 失误次数: number, 减耗: number): number {
  return 线数 + Math.max(0, 失误次数 - Math.max(0, 减耗));
}
// 新
export function 算精神力消耗(线数: number, 失误次数: number): number {
  return 线数 + 失误次数;
}
```

`治疗参数.减耗` 字段一并删除。

> **代价要说清楚**：`算线数` 里那个「第几次 / 预计次数」的调节还在，但「一张好床减少失误惩罚」
> 这条**手感线没有了**。替代它的是 §7.3 —— 好床体现在**结算文案**上，而不是失误次数上。

## 8. 变量结构

```yaml
诊所:
  名称: ''
  等级: D                # D/C/B/A/S
  名声: 0
  气氛: 0                # ★ 派生：Σ 已摆放家具的氛围
  家具: []               # ★ [{ 名称, 类型, 氛围, 在哪 }]，在哪 = '' 即在仓库
```

**前序 §11 的 `诊所.床位` 与 `诊所.摆位` 都删掉**，合并成 `诊所.家具` 一个数组：

| 前序 | 现在 | 为什么 |
|---|---|---|
| `床位: 1` | 派生自 `家具` | 一个数不能表达「哪间房有床」 |
| `家具: {id: {...}}` | `家具: [{...}]` | 数组天然允许同款买两件 |
| `摆位: {'一号·北': id}` | 每件家具自己的 `在哪` 字段 | **一个真值源**，不会出现「摆位指向一个不存在的 id」 |

`在哪` 的格式是 **`${房间}·${方位}`**，例如 `一号·北` / `三号·西`。
前序 §11 的 `'一层·中'` 被这个格式取代。

派生值分两种，**不要混为一谈**：

**(a) 现算的（纯函数，不进 schema）** —— 用到时从 `家具` 数组里算：

```
摆位    = 家具 里 在哪 ≠ '' 的那些，按 在哪 建索引
仓库    = 家具 里 在哪 = '' 的那些
床位    = 已摆放家具里 类型 = '床' 的件数
```

**(b) 持久化的派生值（进 schema，由 zod transform 重算）** —— 只有 `气氛` 一个。

它照 `$称号` 的既有做法：**写在 schema 里、每次解析时重算**，不靠谁记得去更新它。
之所以不跟 (a) 一样现算，是因为它要被状态栏和结算两处读，且前序 §11 已经把它定成变量了
—— 顺着既有做法走，比新发明一个稳。

### 8.1 存档迁移

老存档里 `诊所.床位 = 1`、没有 `家具`。新 schema 下派生出来的床位会是 **0** ——
等于把所有人的开局那张床弄丢了。

**修法：`诊所.家具` 为空时，播种一张折叠床并摆在一号房的 `北`。** 幂等 —— 写回一次之后
`家具` 就不空了。（不做「卖掉所有家具」这种事，所以空 == 开局态。）

## 9. 界面：手风琴三块

`界面/主界面/App.vue` 现在只有**一个**折叠按钮（`<span>诊所与申请</span>`，
展开体是 `<StatusPanel />`）。改成**三个互斥按钮**：

```
诊所 ｜ 申请 ｜ 家园
```

- 默认**全部折叠**，一次只开一块（点新的自动关旧的）
- 展开体和按钮同层，不再有里外两层折叠
- 角标带折叠态的信息：`申请 ③` = 待接数，`家园 ①` = 仓库里有几件没摆

`状态栏/App.vue` 因此**拆成两个组件**：

| 块 | 内容 |
|---|---|
| **诊所** | 招牌（名称 / 等级 / 称号）、名声条、精神力条、姓名 / 金钱 / 床位、日期时段 |
| **申请** | 待接申请列表、待登记、今日已接，以及治疗小游戏的浮层 |
| **家园** | 新增：L2 九宫格，点房间进 L3（§4） |

### 9.1 必须继续用 `v-show`，不能用 `v-if`

**这是一条硬约束。** `状态栏/App.vue:120` 的 `盯住日期` 是**掷骰与申请列表流转的唯一入口**，
它挂在「常驻挂载、`v-show` 折叠」这个前提上（那行上面的注释写明了）。

改成 `v-if` 之后，折叠的块会被**销毁**，`盯住日期` 的 watch 跟着没 ——
**掷骰和申请列表整个死掉，而且不报错**，只是永远不出现新申请。

三个块**全部常驻挂载**，只切换 `v-show`。

### 9.1.1 治疗浮层要挪到块外面

`状态栏/App.vue:57` 的治疗浮层是 `position: fixed` 的（`.诊所__罩`），但它**挂在块内部**。
折叠本来就会把它藏掉（今天就有这个问题，只是折叠不容易误触）；拆成三块之后，
治疗进行中点一下「诊所」就能让整个浮层消失，而**治疗状态还在**。

所以浮层要**挂到三个块之外**（`主界面/App.vue` 里，或用 `Teleport` 到 `body`）。
它不属于「申请」这一块的内容，是盖在整个界面上的。

### 9.2 正文区不动

用户早先说过「点击家园的时候，直接把正文的那块展现的地方，切换成九宫格」。
**这一版不做。** 家园是手风琴里的第三块，展开后占满界面主体的宽度，正文区保持原样。

理由：说那句话在选「手风琴互斥」**之前**；而 L2/L3 已经有两层下钻，再叠一个「正文区换掉」
会让「我现在在哪一层」变得难判断。

### 9.3 状态栏加气氛

前序 §12 要求状态栏显示气氛值。§7.1 的档位描述（`0–19 有点冷清` / `20–39 还算整洁` /
`40–59 待着舒服` / `60+ 让人不想走`）一并落地，放在诊所块的床位旁边。

**这一节是「删已上线代码」的完整名单。** 漏一处的后果见 §12 R1。

| 文件 | 动作 |
|---|---|
